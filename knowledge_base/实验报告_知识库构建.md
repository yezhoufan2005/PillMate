# 家庭用药 MRAG 系统知识库构建实验报告

> 可用于课程设计论文"数据准备与知识库构建"章节

---

## 1. 实验背景与目标

### 1.1 项目背景

本课题旨在设计面向家庭用药管理的**多模态检索增强生成（MRAG）问答系统**。用户可通过上传药片图像或输入药物名称/文字描述，系统自动识别药物并返回药物详细信息与用药建议。

### 1.2 知识库构建目标

MRAG 系统的核心基础是**药物知识库**，需要同时满足以下三类需求：

| 需求类型 | 具体内容 |
|---------|---------|
| **图像数据** | 药片多角度照片（正面/背面/消费者拍摄/专业参考图） |
| **物理属性** | 颜色、形状、印记、尺寸、剂量等药片外观特征 |
| **药物说明书** | 适应症、用法用量、禁忌症、警告、副作用、药物相互作用等完整临床文本 |

### 1.3 核心挑战

- ePillID 数据集的 NDC 编码已过期/注销，无法通过 openFDA 等官方 API 查询
- 包含历史药物数据的 Drugs.com 网站存在严格的反爬虫机制
- 需要在大规模自动化与数据完整性之间取得平衡

## 2. 数据集分析

### 2.1 ePillID 数据集概况

| 指标 | 数值 |
|------|------|
| 总图像数 | 13,534 张 |
| 药片种类 | 4,902 种外观类别 |
| 数据来源 | NIH Pillbox（参考图像）+ NIH 药片识别挑战赛（消费者图像） |
| NDC 格式条目 | 5,728 张 / 928 种 unique NDC |
| SHA hash 条目 | 7,804 张 / 3,902 种（无 NDC，无法映射药物信息） |

### 2.2 数据结构

```csv
images,pilltype_id,label_code_id,prod_code_id,is_ref,is_front,image_path,label
0.jpg,51285-0092-87_BE305F72,51285,92,False,False,fcn_mix_weight/dc_224/0.jpg,51285-0092-87_BE305F72
```

- `pilltype_id`：格式为 `{NDC编码}_{哈希值}`，前半部分为 NDC（如 `51285-0092-87`），后半部分为特征哈希
- `is_ref`：是否为专业参考图像
- `is_front`：是否为药片正面图像

### 2.3 关键发现

经分析发现，13,534 张图像中仅 **5,728 张（42.3%）** 包含可用的 NDC 编码，其余 7,804 张为 NIH Pillbox 的 SHA hash 编码，无法与药物信息建立关联。因此本实验最终以 **928 种 unique NDC 对应 5,728 张图像** 作为知识库基础。

## 3. 数据源调研与方案选型

### 3.1 候选数据源对比

| 数据源 | 图像 | NDC | 说明书 | 可用性 | 结论 |
|--------|:--:|:--:|:--:|--------|:--:|
| openFDA API | ✗ | ✓ (仅有效) | ✓ 基础 | API 稳定 | ❌ 过期NDC无法查询 |
| DailyMed | ✗ | ✓ (仅有效) | ✓ 完整 | API 有技术障碍 | ⚠️ 需配合RxNorm |
| Drugs.com | ✓ | ✓ (含历史) | ✓ 完整 | 严格反爬 | ❌ 自动化不可行 |
| RxNorm API | ✗ | ✓ (含历史) | ✗ | API 稳定 | ✅ NDC桥接层 |

### 3.2 反爬虫测试

针对 Drugs.com 测试了三种自动化方案：

| 方案 | 技术 | 结果 | 原因 |
|------|------|:--:|------|
| requests | HTTP 直接请求 | ❌ | CDN 层 403 Forbidden |
| Selenium | 浏览器自动化 | ⚠️ | SSL 握手错误 + 不稳定 |
| Playwright | 浏览器自动化 | ❌ | Akamai EdgeSuite 检测到自动化特征 |

**结论**：Drugs.com 的 CDN（Akamai）和反爬机制无法通过常规自动化手段绕过，不适合大规模数据采集。

### 3.3 最终方案选择

通过实验对比，确定了 **"RxNorm + DailyMed SPL"** 作为最终方案：

```
ePillID 过期 NDC
      │
      ▼ RxNorm API (100% 映射成功率)
  rxcui (药物本体 ID)
      │
      ▼ DailyMed SPL XML (94.2% 覆盖率)
  完整药物说明书 + 物理属性
```

**选择理由**：
- RxNorm 是 NIH 官方 API，支持**历史 NDC 映射**，解决了过期 NDC 无法查询的核心问题
- DailyMed SPL XML 是 FDA 官方药品说明书标准格式，包含 Drugs.com 所有的药物信息字段
- 全链路零反爬、全自动、可复现

## 4. 知识库构建实验

### 4.1 构建管线

知识库构建分为五个阶段：

```
Phase 1: NDC 提取
  ePillID all_labels.csv → 正则匹配 → 928 unique NDCs → data/unique_ndc_list.json

Phase 2: RxNorm 映射
  NDC → RxNorm API (/ndcstatus.json) → rxcui + OBSOLETE/ACTIVE 状态

Phase 3: DailyMed SPL 检索
  rxcui → DailyMed API (/spls.json) → SPL setid 列表

Phase 4: SPL XML 解析
  setid → DailyMed SPL XML → 结构化提取: 药物名称、制造商、物理属性、9个说明书章节

Phase 5: 知识库优化
  数组→字典化 → 扁平化字段 → RAG 文本预拼接
```

### 4.2 SPL XML 解析的技术难点

#### 难点 1：XML 被 HTML 污染
DailyMed 的 `.xml` 端点返回的响应被注入了 Google Tag Manager 脚本，导致 XML 解析失败。解决方案是使用 `/services/v2/spls/{setid}.xml` 端点获取纯净 XML。

#### 难点 2：制造商字段定位
制造商信息不在预期的 `<manufacturingOrganization>` 标签中，而是在 `<representedOrganization>` 标签中。通过诊断脚本遍历 SPL XML 结构后确定了正确路径。

#### 难点 3：物理属性提取
颜色、形状、印记等物理属性分散在两个位置：
1. **文本层面**：`HOW SUPPLIED` 和 `DESCRIPTION` 章节的自然语言描述
2. **结构化层面**：`<manufacturedProduct>` 中的 `<value>`（印记编码）和 `<originalText>`（外观描述）

通过结合 NLP 正则提取和 XML 结构化提取实现物理属性的完整获取。

### 4.4 54 个 DailyMed 缺失 NDC 分析

928 个 NDC 中有 54 个在 DailyMed 中无对应 SPL 文档（覆盖率 94.2%）。经分析主要原因包括：
- 部分 NDC 对应的是**组合产品**（如避孕药 Kit），DailyMed 的 rxcui 映射不完整
- 部分 NDC 对应的药物已被制造商撤市且未保留 SPL 归档
- 少数 NDC 属于非常用规格，在大规模 SPL 文档库中未收录

## 5. 知识库设计与数据结构

### 5.1 文件夹结构

```
knowledge_base/
├── README.md              # 使用说明文档
├── database.json           # 核心知识库 (46.2 MB, 928 药物)
└── images/                 # 药片图像 (5,728 张)
    ├── 00093-0148-01/      # NDC 为文件夹名
    │   ├── 10.jpg
    │   ├── 1299.jpg
    │   └── ...
    └── ...                 # 共 928 个文件夹
```

### 5.2 database.json 数据结构

核心设计理念：**NDC 编码作为唯一主键**，实现图像与药物信息的一对一映射。

```json
{
  "stats": {
    "total_ndc": 928,
    "status_counts": { "success": 874, "dailymed_miss": 54 },
    "rag_coverage": { "has_rag_text": 894, "has_physical_properties": 874 }
  },
  "drugs": {
    "00093-0148-01": {
      "ndc": "00093-0148-01",
      "image_count": 7,
      "image_paths": ["fcn_mix_weight/dc_224/10.jpg", ...],
      "drug_name": "Naproxen",
      "generic_name": "naproxen",
      "manufacturer": "Sportpharm LLC",
      "physical_properties": [
        { "strength": "375 mg", "color": "yellow", "shape": "capsule",
          "imprint": "sg / 435" }
      ],
      "indications": "1 INDICATIONS AND USAGE ...",
      "warnings": "WARNING: RISK OF SERIOUS ...",
      "contraindications": "4 CONTRAINDICATIONS ...",
      "dosage_administration": "2 DOSAGE AND ADMINISTRATION ...",
      "adverse_reactions": "6 ADVERSE REACTIONS ...",
      "clinical_pharmacology": "12 CLINICAL PHARMACOLOGY ...",
      "drug_interactions": "7 DRUG INTERACTIONS ...",
      "overdosage": "10 OVERDOSAGE ...",
      "rag_text": "DRUG NAME: Naproxen\n...\n\nINDICATIONS:\n..."
    }
  }
}
```

### 5.3 NDC 作为桥梁的设计

```
                 NDC: 00093-0148-01
                        │
          ┌─────────────┴─────────────┐
          ▼                           ▼
   images/00093-0148-01/        drugs["00093-0148-01"]
   ├── 10.jpg                  ├── drug_name: Naproxen
   ├── 1299.jpg                ├── physical_properties: [...]
   └── 2456.jpg                ├── indications: "..."
                               └── rag_text: "..."
```

MRAG 系统运行时只需通过 NDC 这一个 key 即可完成图像到药物信息的全链路查询。

### 5.4 RAG 文本预拼接设计

为提升 MRAG 系统效率，预先将所有章节拼接为 `rag_text` 字段：

```
DRUG NAME: Naproxen
GENERIC NAME: naproxen
MANUFACTURER: Sportpharm LLC
APPEARANCE: 375 mg yellow capsule imprint sg / 435

INDICATIONS AND USAGE:
1 INDICATIONS AND USAGE Naproxen Tablets are indicated for...

DOSAGE AND ADMINISTRATION:
2 DOSAGE AND ADMINISTRATION Use the lowest effective dosage...

CONTRAINDICATIONS:
4 CONTRAINDICATIONS Naproxen tablets are contraindicated...

WARNINGS AND PRECAUTIONS:
WARNING: RISK OF SERIOUS CARDIOVASCULAR AND GASTROINTESTINAL EVENTS...

ADVERSE REACTIONS:
6 ADVERSE REACTIONS The following adverse reactions...

CLINICAL PHARMACOLOGY:
12 CLINICAL PHARMACOLOGY 12.1 Mechanism of Action...

DRUG INTERACTIONS:
7 DRUG INTERACTIONS See Table 1...

OVERDOSAGE:
10 OVERDOSAGE Symptoms following acute NSAID overdosages...
```

该文本可直接作为 ChromaDB 或 FAISS 向量数据库的输入，无需运行时动态拼接。

## 6. 实验总结

### 6.1 主要成果

1. 成功构建了包含 **928 种药物**、**5,728 张药片图像**、**完整 9 章说明书**的多模态知识库
2. 解决了 ePillID 过期 NDC 的映射问题，通过 RxNorm 实现了 **100% 的 NDC 到药物本体映射**
3. 绕过了 Drugs.com 的反爬限制，通过 DailyMed SPL XML 实现了 **94.2% 的药物说明书覆盖率**
4. 设计了以 NDC 为唯一键的知识库结构，实现了图像与药物信息的高效关联
5. 预拼接 RAG 文本，为后续 MRAG 系统提供了即用型知识库

### 6.2 技术亮点

- **多源数据融合**：ePillID（图像）+ RxNorm（NDC 映射）+ DailyMed（说明书）
- **全自动化管线**：从 NDC 提取到知识库输出的端到端自动处理
- **断点续传机制**：928 个 NDC 的大规模处理中实现了 checkpoint 自动保存
- **结构化 + 自然语言混合提取**：XML 结构化解析 + 正则文本提取相结合，最大化信息获取

### 6.3 不足与改进方向

1. **印记覆盖率偏低（45.1%）**：部分 SPL 的物理属性完全以自然语言描述，正则提取有遗漏。可通过引入基于 LLM 的文本结构化提取进一步提升
2. **54 个 DailyMed 缺失药物**：可尝试通过 PubMed、其他学术数据库或人工补充
3. **图像来源于单一数据集**：ePillID 数据集的图像质量和角度有限，可考虑引入更多来源的药片图像
4. **中文药物名称缺失**：目前知识库以英文为主，可引入中英文药物名称映射以支持中文查询
